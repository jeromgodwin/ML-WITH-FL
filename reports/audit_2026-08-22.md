## CRITICAL

**C1 — In-memory rate limiter & last-seen not distributed**
*Where:* `backend/security/rate_limiter.py:11`, `backend/services/client_service.py:11` (`_last_seen`, `_last_fl`)
*Risk:* Multiple server replicas would have independent limits; restart loses `last_seen`.
*Impact:* Bypass rate limiting, lost client presence.
*Recommendation:* Redis or DB-backed store for Tier 2.

**C2 — Self-signed TLS docs hidden but no CA verification for LAN**
*Where:* `src/federated/network/tls.py:24` (`_create_unverified_context` fallback when cert missing, `secure=true` without `ca_cert`)
*Risk:* Internet deployment with self-signed without `ca_cert` is vulnerable to MITM; `docs` hidden is good but TLS still unverified.
*Recommendation:* Require `ca_cert` when `host` is not `127.0.0.1`/`localhost` if `secure=true`.

**C3 — DP high-dim collapse not mitigated**
*Where:* `src/federated/privacy/dp.py:44` (per-update clipping + per-coordinate Gaussian `sigma=C*multiplier`, 642k dim → noise norm ~800 for sigma 1.0)
*Risk:* Privacy-utility trade-off is catastrophic (F1 0.845→0.11, `data/final_phase23_H`), users may enable DP expecting modest loss.
*Recommendation:* Document as known limitation (already in `reports/phase24_final_analysis.md`), offer per-layer clipping or dimension-aware noise in Tier 3.

## HIGH

**H1 — Hardcoded `127.0.0.1` still present in FL server fallback**
*Where:* `src/federated/fl/server.py:441` (`bind_host = "127.0.0.1"` when `host` is `127.0.0.1`/`localhost`, otherwise `0.0.0.0`)
*Risk:* LAN/Internet clients cannot connect to in-process FL server (binds to loopback only for local sim). Internet deployment requires separate Flower server process not yet provided.
*Recommendation:* Document that in-process `run_fl_experiment` is for research; production FL server must bind `0.0.0.0` with TLS certs (Tier 2, Enhancement 24).

**H2 — Model registry history in-memory + JSON, not atomic**
*Where:* `src/federated/model_registry/__init__.py:389` (`history.json` write not atomic, `_save_index` no lock)
*Risk:* Concurrent `register`/`rollback` could corrupt `index.json`/`history.json`.
*Recommendation:* File lock or SQLite for Tier 1 (Enhancement 2).

**H3 — Client `token_hex(32)` stored plaintext in `clients.json`**
*Where:* `src/federated/network/auth.py:28` (`ClientRegistry` JSON)
*Risk:* If `data/server_registry/clients.json` leaked, all client tokens compromised.
*Recommendation:* Hash tokens (e.g., `hmac-sha256`) and store hash only; compare via hash.

**H4 — No file-upload antivirus guarantee relies on validation, but frontend has no upload**
*Where:* `frontend/src/api.js:1` correctly has no upload, `backend/app.py:140` rejects `raw_file`, but `backend/secure_app.py:95` duplicate logic
*Risk:* Duplicated validation (two apps) could diverge.
*Recommendation:* Unify validation in `network/validation.py` and import in both apps (deduplicate).

**H5 — Resource battery on CI is `None` (simulated)**
*Where:* `src/endpoint/resource/monitor.py` (`psutil.sensors_battery()` returns `None` on Windows CI)
*Risk:* Low-battery behavior never tested on real hardware.
*Recommendation:* Manual test on laptop with battery, document as limitation (already in `phase23_final_report.md`).

## MEDIUM

**M1 — Duplicated code: `export_bundle` vs `InferenceBundle` vs `ModelRegistry`**
*Where:* `src/federated/model_bundle.py:40`, `src/federated/model_registry/__init__.py:113`, `src/interfaces/__init__.py:15`
*Impact:* Three places handle `FeatureSchema`/`ModelMetadata` serialization slightly differently.
*Recommendation:* Consolidate via single `ModelMetadata` helper.

**M2 — Dead code: `scripts/ember_ref/features.py` warnings**
*Where:* `scripts/ember_ref/features.py:67` `RuntimeWarning: invalid value encountered in divide` (seen in 31 warnings)
*Impact:* No functional harm, but noisy logs hide real warnings.
*Recommendation:* Guard `counts / sum` with `where sum !=0`.

**M3 — Performance bottleneck: `X_train` memmap → `gather()` double load (fixed in Phase 15)**
*Where:* `src/federated/experiments/engine.py:230` (fixed to reuse memmap), but `src/federated/training/centralized.py:30` still materializes `Xtr`/`Xva` fully in RAM (7.6 GB + 1.9 GB)
*Impact:* 16 GB laptop needs per-cell fresh process (Phase 14 fix) to avoid OOM.
*Recommendation:* Keep chunked `gather()` and per-cell subprocess for Tier 1 (Enhancement 9).

**M4 — Poor error handling: `HistoryStore` `INSERT OR REPLACE` swallows `sqlite3` errors**
*Where:* `src/endpoint/history/__init__.py:65`
*Impact:* Corrupted detection record could be silently overwritten.
*Recommendation:* Log exception and return error record (already does for detector, but not for history).

**M5 — Missing tests: `frontend` no Playwright E2E**
*Where:* `frontend/src/components/*` (11 tabs) only `vite build` verified, no `tests/test_frontend.py`
*Impact:* Dashboard regression not caught by `pytest`.
*Recommendation:* Add `test_control_center.py` covers API, but add Playwright for Tier 1 (Enhancement 27).

**M6 — Hardcoded configuration in `configs/default.yaml` vs `ServerNetworkConfig` defaults**
*Where:* `configs/default.yaml:131` (`host: 127.0.0.1`) and `fedshield/config.py:281` (`host: 127.0.0.1`) duplicated
*Impact:* Change in one not reflected in other if edited manually.
*Recommendation:* Keep `default.yaml` as single source, `config.py` defaults as fallback (already, but document).

**M7 — Platform assumptions: `quarantine/` and `data/` paths assume `D:\ML with FL` (Windows)**
*Where:* `src/endpoint/quarantine/__init__.py`, `src/federated/model_registry/__init__.py` (`Path("data")`)
*Impact:* Linux/Mac paths work but `quarantine` location not configurable per OS.
*Recommendation:* Make `quarantine_dir` and `data_dir` explicit in ` configs/default.yaml` (already, but not used everywhere).

*Recommendation:* Cache and watch file mtime.
